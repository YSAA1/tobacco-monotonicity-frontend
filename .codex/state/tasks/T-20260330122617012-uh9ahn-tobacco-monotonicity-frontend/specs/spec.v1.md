# 任务规格 v1

- task_id: T-20260330122617012-uh9ahn-tobacco-monotonicity-frontend
- 标题: tobacco-monotonicity-frontend
- lane: planned_build
- 目标: 构建一个中国烟草主题的数据前端，支持导入 Excel 数据，检查第三十档到第一档是否满足单调不增，并将不满足的记录高亮标记出来

## 澄清问题

- 已确认：首版产品以“单页高质感数据工作台”为交付边界。

## 目标

- 用户可以在浏览器中导入符合当前模板结构的 Excel 文件。
- 系统自动识别从 `三十档` 到 `一档` 的 30 个档位列，并执行单调不增校验。
- 对不满足 `当前档 >= 下一档` 的记录进行显著标记，并展示违规位置与原因。
- 提供高完成度的“中国烟草”主题视觉界面，包含非 emoji 的品牌化图形、真实图片位和大屏感布局。

## 边界

- v1 仅处理与当前样例一致或高度接近的单表 Excel 模板。
- v1 以浏览器本地解析和本地校验为主，不依赖后端服务。
- v1 聚焦“导入、分析、筛选、标记、导出结果视图”这一条主流程。
- v1 可以包含首页级视觉包装，但核心仍是数据工作台而不是内容门户。

## 非目标

- 不做用户登录、角色权限、数据库持久化。
- 不做复杂工作流审批、历史任务管理、消息通知。
- 不做通用任意表格识别；首版不支持完全不同列名和乱序字段。
- 不直接使用可能涉及授权问题的官方商标素材；视觉上采用“中国烟草行业”语义化设计而非冒用正式标识。

## 关键约束

- 已确认当前样例 Excel 为单 sheet，共 36 列，其中第 7 列到第 36 列为 `三十档` 到 `一档`。
- 当前业务规则明确为：对每一行，必须满足 `三十档 >= 二十九档 >= ... >= 一档`。
- 当前样例数据中未发现违规记录，因此实现阶段需要自造测试数据或构造演示违规样例验证前端标记效果。
- 当前仓库没有前端工程基础，因此技术选型要优先降低搭建阻力，同时保留高级视觉表达空间。

## Done When

- 可以导入当前格式的 Excel 文件并成功展示解析结果。
- 系统能对每行数据完成单调不增检查，并给出总记录数、违规记录数、违规位置明细。
- 违规行在表格和详情视图中均有清晰视觉标记。
- 页面具备完整的高保真视觉主题，包括 logo 区、主题头图/实拍图位、关键指标区、数据分析区和结果表格区。
- 至少有一组可复现实例证明违规检测与高亮逻辑正确。

## 已确认事实

- 仓库当前只有一个 Excel 文件，没有现成前端或后端代码。
- 样例文件 `数据服务_20260329135909181.xlsx` 只有一个工作表 `Sheet0`。
- 样例文件共 38 条数据，当前没有违反单调不增规则的记录。

## 方案比较

### 方案 A：极简上传工具页

- 优点：实现最短，技术风险最低。
- 缺点：无法承载你要求的“高大上复杂”视觉体验，产品表现力明显不够。
- 返工风险：后续若再扩展为高保真产品，页面结构大概率重做。
- 现在不选的理由：与需求中的视觉诉求直接冲突。

### 方案 B：单页高质感数据工作台

- 优点：既能保证核心流程聚焦，又有足够空间做大屏级视觉、品牌头图、统计卡片、筛选区和异常明细区。
- 缺点：前端页面编排和视觉资产要求高于工具页。
- 返工风险：中等，可在后续平滑扩展为多页面系统。
- 现在选的理由：最符合“复杂但可控”的首版交付目标。

### 方案 C：多页面品牌门户 + 工作台

- 优点：展示力最强，可做首页、数据中心、帮助页、品牌介绍等完整体验。
- 缺点：范围明显膨胀，当前还没有足够业务内容支撑多页面信息架构。
- 返工风险：高，容易先把精力耗在包装页而不是校验主流程。
- 现在不选的理由：首版最小交付物会被稀释，工程成本与业务价值不匹配。

## 推荐路线

- 推荐采用方案 B：单页高质感数据工作台。
- 页面结构建议分为：品牌头部、数据导入区、检测摘要区、违规筛选区、分析图表区、结果表格区、违规详情抽屉。
- 视觉方向建议使用“烟叶纹理 + 赤金配色 + 深墨绿底 + 中式印章感 logo”的行业主题，但避免直接复刻官方标识。

## 页面结构

- 顶部 Hero 区：品牌 logo、系统标题、副标题、主题图片、导入入口按钮。
- 数据导入区：拖拽上传、模板说明、文件解析状态、错误提示。
- 检测摘要区：总记录数、合规数、违规数、违规率、最近导入文件名。
- 规则说明区：用可视化文案说明 `三十档 >= ... >= 一档` 的判定逻辑。
- 分析图表区：展示档位分布概览、违规对比统计、合规/违规占比。
- 结果表格区：展示商品信息与 30 档数据，支持筛选“全部 / 仅违规”。
- 违规详情抽屉：点击某条记录后展开，逐段显示哪两个相邻档位违反了单调不增。

## 关键交互流程

1. 用户打开页面，先看到品牌化头图和功能入口。
2. 用户导入 Excel 文件，前端本地完成解析。
3. 系统校验表头是否包含 6 个元数据列和 30 个档位列。
4. 解析成功后生成行级检测结果、汇总指标和图表数据。
5. 默认展示全部数据，同时对违规行做高对比标记。
6. 用户可切换只看违规项，并打开详情抽屉查看具体违规档位对。

## 数据与状态设计

- 输入数据模型：
  - 元数据字段：`商品编码`、`商品名称`、`批发价`、`投放方式`、`合计（最终投放量）`、`合计(档位）`
  - 档位字段：`三十档` 到 `一档`
- 行级检测结果：
  - `isValid`
  - `violations`
  - `rankValues`
- 页面核心状态：
  - `fileStatus`
  - `rawRows`
  - `analyzedRows`
  - `summaryMetrics`
  - `filterMode`
  - `selectedRow`

## 规则定义

- 单调不增定义：按列顺序从 `三十档` 到 `一档` 依次检查，要求前一个值大于或等于后一个值。
- 若任意相邻两档出现 `前值 < 后值`，该行判定为违规。
- 每条违规记录需要输出：
  - 违规相邻档位名称
  - 对应两个数值
  - 该行是否整体违规
- 空值处理首版按 `0` 处理，但仅适用于当前模板内的数值列。

## 技术路线

- 前端框架建议：React + Vite + TypeScript。
- Excel 解析建议：浏览器端使用 `xlsx` 或同类库本地读取。
- 图表建议：使用轻量但视觉可控的图表库，优先 `recharts`。
- 样式建议：使用 CSS Modules 或单独主题样式文件，避免过重 UI 框架限制视觉表达。
- 资源组织建议：独立 `assets/` 放 logo、纹理图、烟叶/烟田实拍图和装饰图形。

## 视觉与素材约束

- 整体风格：深墨绿、赤金、米白、烟叶棕，强调行业感和质感，不做互联网通用后台风格。
- logo 采用自制几何图形或印章式字标，不使用 emoji。
- 页面应有真实图片位，推荐使用烟叶、烟田、卷烟工艺或仓储质检语义图片。
- 不直接复刻“中国烟草”官方 logo 或带明显权属风险的视觉资产。
- 移动端需可用，但优先优化桌面端大屏展示。

## 首批高风险改动面

- Excel 解析层：表头识别、数值归一化、空值处理。
- 检测逻辑层：违规对定位和明细生成。
- 数据表格层：高亮、筛选、详情联动。
- 视觉资源层：主题素材和 logo 的合法替代设计。
